# 02. 想定シナリオ（個人 5ケース / 法人 6ケース）

各ケースは「誰が / どんな状況で / どう使い / 何が嬉しいか / 必要な機能」で整理する。

## Part A. 個人（toC）

### ケース C-1: 外出先から自宅周辺の豪雨を確認する

| 項目 | 内容 |
| --- | --- |
| ペルソナ | 30代 会社員、川沿いのマンションに一人暮らし |
| 状況 | 勤務中に「線状降水帯発生」のニュース。自宅近くの川が心配 |
| 使い方 | 1. 「大雨警報（自宅エリア）」の通知を受け取る<br>2. 自宅地点のタイムラインを開く<br>3. 公式: 洪水警報・キキクル危険度 / SNS: 「〇〇川の水位が上がってる」「△△交差点が冠水」などの投稿を確認<br>4. 地点の画面のリンクから、近くの河川の水位・カメラの公式ページを開いて確認<br>5. 地図で冠水投稿の位置と帰宅ルートを照らし合わせる |
| 嬉しいこと | 帰宅するか・どの道で帰るかを判断できる |
| 必要機能 | 地点登録、警報通知、公式/SNS 区別表示、地図表示、河川の水位・カメラの公式ページへのリンク |

### ケース C-2: 離れて暮らす親の地域で地震が起きた

| 項目 | 内容 |
| --- | --- |
| ペルソナ | 40代、東京在住。両親は地方で二人暮らし |
| 状況 | 夜中に実家のある地域で震度5弱の地震 |
| 使い方 | 1. 「実家」地点で地震通知（震度4以上で通知に設定）<br>2. タイムラインで震度・震源を確認<br>3. SNS で「停電してる」「〇〇町で瓦が落ちた」など周辺の被害状況を把握<br>4. 状況を見て両親へ電話<br>5. 家族グループに入っている親が「無事」を報告すると、タイムラインに表示される |
| 嬉しいこと | 電話がつながらない間も、周辺の状況と親の無事がわかって落ち着ける |
| 必要機能 | 複数地点登録、通知しきい値設定（震度）、地震情報取り込み、現地からの報告（家族共有と組み合わせる） |

### ケース C-3: 海沿いの自宅で津波警報が出た

| 項目 | 内容 |
| --- | --- |
| ペルソナ | 60代夫婦、海岸から1kmほどの住宅に住む |
| 状況 | 沖合で地震が発生し、沿岸に津波警報 |
| 使い方 | 1. 自宅地点で「津波: 注意報以上を通知」に設定済み → 即時通知<br>2. タイムラインで津波警報の対象区域・予想高さ・到達予想時刻を確認<br>3. SNS で「〇〇港で潮が引いている」「高台に避難中」などの投稿を参考に把握<br>4. 指定避難場所へ避難を開始 |
| 嬉しいこと | テレビをつける前にスマホで要点がわかり、避難の判断が早くなる |
| 必要機能 | 津波情報の取り込み、津波のしきい値設定、沿岸地点判定、即時通知 |

### ケース C-4: 子どもの学校・通学路を見守る

| 項目 | 内容 |
| --- | --- |
| ペルソナ | 小学生の子を持つ保護者 |
| 状況 | 登校時間帯にゲリラ豪雨・雷 |
| 使い方 | 1. 「学校」「通学路の途中（川・アンダーパス付近）」を地点登録<br>2. 学校の地点に大雨警報・記録的短時間大雨情報が出たら Web Push で通知（SNS の投稿だけでは通知しない）<br>3. 通知からタイムラインを開き、冠水などの SNS 投稿も合わせて確認<br>4. 学校からの連絡を待つ間に周辺状況を確認し、迎えに行くか判断 |
| 嬉しいこと | 学校の一斉メールより早く、周辺の様子がわかる |
| 必要機能 | 複数地点・ラベル名設定、時間帯指定の通知（通学時間のみ等） |

### ケース C-5: 家族で同じ地点を共有して見る

| 項目 | 内容 |
| --- | --- |
| ペルソナ | 夫婦＋大学生の子ども（別々の場所にいることが多い） |
| 状況 | 台風接近。家族それぞれが自宅・職場・大学にいる |
| 使い方 | 1. 代表者が「家族グループ」を作成し招待リンクを共有<br>2. 自宅・各自の職場・大学を共有地点として登録<br>3. 全員が同じタイムライン・地図を見ながら LINE で相談<br>4. 「誰がいつ帰るか」「どこで合流するか」を決める |
| 嬉しいこと | 家族全員が同じ情報を見ながら判断できる |
| 必要機能 | 家族共有（招待リンク）、共有地点、LINE 通知（有料プラン候補） |

## Part B. 法人（toB）

### ケース B-1: 多店舗チェーンの営業可否判断

| 項目 | 内容 |
| --- | --- |
| ペルソナ | 飲食・小売チェーン（50店舗）の店舗運営部 |
| 状況 | 豪雨で複数エリアに大雨・洪水警報 |
| 使い方 | 1. CSV で全店舗を一括登録済み<br>2. ダッシュボードで「警戒」ステータスの店舗を一覧表示<br>3. 各店舗のタイムラインで「店舗前の道路が冠水」などの現地投稿を確認<br>4. 営業短縮・臨時休業を店舗に指示 |
| 嬉しいこと | 店舗へ1件ずつ電話する前に、全体の状況をつかめる |
| 必要機能 | CSV一括登録、拠点ダッシュボード（ステータス一覧）、地図ビュー |

### ケース B-2: 地震発生時の BCP 初動（拠点の被害把握）

| 項目 | 内容 |
| --- | --- |
| ペルソナ | 製造業の総務・BCP 担当（工場 5 / 営業所 20） |
| 状況 | 平日昼に震度6弱の地震 |
| 使い方 | 1. 震度5弱以上の拠点があれば Slack の #bcp チャンネルに自動通知<br>2. 通知から影響のある拠点リストを開く<br>3. 影響のある拠点の責任者に「状況確認の依頼」が自動で届き、「被害なし」「被害あり（停電・建物・人）」を回答してもらう<br>4. 回答の集計と各拠点周辺の SNS 投稿（停電・建物被害・道路寸断）を合わせて確認<br>5. 対策本部の立ち上げ判断と、回答がない・被害ありの拠点から優先して確認 |
| 嬉しいこと | 初動の「何が起きているか分からない」時間を短くできる。拠点へ1件ずつ電話しなくてよい |
| 必要機能 | 震度しきい値通知、Slack/Teams 連携、影響拠点の自動抽出、状況確認の依頼と回答の集計 |

### ケース B-3: 物流・配送ルートの運行判断

| 項目 | 内容 |
| --- | --- |
| ペルソナ | 運送会社の配車担当 |
| 状況 | 配送エリアでゲリラ豪雨・道路冠水の情報 |
| 使い方 | 1. 物流センター・主要配送エリアを地点（半径広め）で登録<br>2. 冠水・通行止め系の投稿を地図で確認<br>3. ドライバーへルート変更・待機の指示<br>4. 荷主へ遅延連絡 |
| 嬉しいこと | 道路の現地状況をリアルタイムに近い形で把握できる |
| 必要機能 | 広域半径の地点、地図上での投稿ピン表示、キーワード（冠水・通行止め）フィルタ |

### ケース B-4: 不動産・施設管理会社の管理物件見守り

| 項目 | 内容 |
| --- | --- |
| ペルソナ | 賃貸マンション管理会社（管理物件 200 棟） |
| 状況 | 夜間の大雨で、山沿いの物件に土砂災害警戒情報、沿岸の物件に津波注意報 |
| 使い方 | 1. 管理物件を全件登録し、物件の立地に応じて種別を設定（山沿い: 土砂災害=警報以上を通知 / 沿岸: 津波=注意報以上を通知）<br>2. しきい値を超えた物件があればメール/Teams 通知<br>3. 当番担当者がタイムラインで状況を確認。夜間の待機中は、ダッシュボードの音声読み上げをオンにして、ほかの作業をしながら新しい情報を聞く<br>4. 入居者への注意喚起・翌朝の現地確認・オーナーへの報告を判断 |
| 嬉しいこと | 物件ごとにリスクに合った情報だけ届き、入居者やオーナーより先に状況を把握できる |
| 必要機能 | 大量拠点の登録、拠点ごとの種別・しきい値設定（CSVでも一括指定）、通知の担当者振り分け、音声読み上げ |

### ケース B-5: 災害後の振り返り・報告書作成

| 項目 | 内容 |
| --- | --- |
| ペルソナ | 総務部・リスク管理部門 |
| 状況 | 台風通過後、経営層への報告と BCP 見直しが必要 |
| 使い方 | 1. 期間・拠点を指定してイベントログを抽出<br>2. 「いつ・どの拠点で・どんな警報/投稿があったか」を時系列で確認<br>3. CSV 出力して報告書・BCP 改善に使う<br>4. 通知のタイミングやしきい値が適切だったか見直す |
| 嬉しいこと | 記憶やチャット履歴に頼らず、記録に基づいて振り返りができる |
| 必要機能 | 履歴の長期保存、期間・拠点指定の検索、CSV エクスポート |

### ケース B-6: 主要な取引先の被災状況を把握する

| 項目 | 内容 |
| --- | --- |
| ペルソナ | 部品メーカー（従業員 100 名）の購買部。主要な仕入先は国内に 30 社 |
| 状況 | 休日の早朝、仕入先が集まる地域で震度6弱の地震 |
| 使い方 | 1. 仕入先の所在地を「取引先」タグ付きの拠点として CSV で登録済み（自社の拠点とは分けて表示）<br>2. 震度5弱以上の取引先があれば、購買部の Slack とメールに通知（休日でも気づける）<br>3. ダッシュボードを「取引先」で絞り込み、影響のある仕入先と周辺の状況を確認<br>4. 影響のある仕入先に連絡し、部品の供給への影響と代わりの調達先を検討 |
| 嬉しいこと | ニュースを見てから仕入先を1社ずつ調べる時間がなくなり、生産への影響を早く見積もれる |
| 必要機能 | 拠点の種別タグ（自社 / 取引先）とタグでの絞り込み、CSV一括登録、Slack/メール通知 |

## Part D. 次に決めること

- [x] 火事は対象外（決定）。対象は大雨・洪水・土砂災害・地震・津波
- [ ] 各種別のデフォルトしきい値（01 の 4.2 案）で問題ないか
- [ ] SNS 投稿の位置推定ロジックの PoC（地名辞書 × 本文マッチング）
- [x] SNS 投稿だけをきっかけに通知しない（決定。人による確認を行わないため → [01](./01_concept_overview.md) 9章）
- [x] 状況確認の回答はログイン不要のワンタイムリンクにする（→ [03](./03_screens.md) P-09、[04](./04_data_model.md) 5.4）
