# 01. コンセプト概要（たたき台）

> ステータス: Draft v0.1 / 2026-10-06
> 目的: サービスの方向性・対象・スコープ・技術方針を揃えるための叩き台

---

## 1. サービス概要

### 1.1 ひとことで

**「登録した場所の周りで、いま何が起きているか」を、公式情報とSNSの“現場の声”をまとめて1本のタイムラインで見られるサービス。**

### 1.2 仮サービス名

- 仮称: **saigai-timeline（サイガイ・タイムライン）**
- 候補: 「まわりみ」「ちかくの防災TL」「Near Alert」など（後で決定）

### 1.3 解決したい課題

| 課題 | 現状 | このサービスで |
| --- | --- | --- |
| 情報が散らばっている | 気象庁・自治体・X・Threads・ニュースを個別に見に行く必要がある | 地点ごとに1つのタイムラインへ集約 |
| 「自分の近くか」が分からない | 全国の投稿が流れてきて、自宅/会社に関係あるか判断しづらい | 登録地点からの距離・エリアで絞り込み |
| 公式発表が遅い / 粒度が粗い | 公式情報は市区町村単位・数分〜数十分遅れ | SNSの現場投稿で「今」を補完（※信頼度ラベル付き） |
| 法人は拠点が多い | 拠点ごとに状況確認するのが手間、BCP初動が遅れる | 複数拠点を一覧・地図で横断監視、通知 |

---

## 2. ターゲット

### 2.1 toC（個人）

- 自宅・実家・子どもの学校・通勤経路など、**気になる場所が数か所ある個人**
- 離れて暮らす家族の地域が心配な人
- 想定登録地点数: 1〜3（無料）、〜10（有料）

### 2.2 toB（法人）

- 複数の拠点（本社・支店・店舗・倉庫・工場）を持つ企業
- 総務 / 防災担当 / BCP担当 / 店舗運営部門
- 物流・小売・不動産管理・建設など「現地の状況」が業務に直結する業種
- 想定登録地点数: 10〜数百

---

## 3. 提供価値（コンセプトの柱）

1. **場所起点（Location First）**
   ニュース起点ではなく「登録した地点」起点で情報を並べる。
2. **公式 × 現場のハイブリッド**
   公式情報（気象庁など）を“確定情報”、SNS投稿を“速報・現場の声”として区別表示する。
3. **ノイズを減らす**
   災害キーワード × 位置情報 × 時間でフィルタし、関係ない投稿を出さない。
4. **低コスト運用**
   サーバーレス中心・無料APIを優先し、個人開発でも維持できる構成にする。

## 4. 対象とする災害種別と警報レベルの選択

> 方針: **火事は対象外**とする（全国共通の公式ソースがないため）。
> 気象庁等の公式情報を軸に、**ユーザーが「どの災害を」「どのレベルから」見る・通知するかを地点ごとに選べる**ようにする。

### 4.1 対象とする災害種別

| 種別 | 主な公式ソース | 公式情報の例 | SNSでの検索例 |
| --- | --- | --- | --- |
| 大雨・洪水 | 気象庁 防災情報XML / 気象庁JSON | 大雨・洪水の注意報/警報/特別警報、記録的短時間大雨情報、線状降水帯 | 「冠水」「大雨」「川が溢れ」+地名 |
| 土砂災害 | 気象庁 | 土砂災害警戒情報、大雨（土砂災害）警報 | 「土砂崩れ」「がけ崩れ」+地名 |
| 地震 | 気象庁 地震情報 / P2P地震情報 API | 震度速報、震源・震度情報 | 「揺れた」「地震」+地名 |
| 津波 | 気象庁 津波情報 / P2P地震情報 API | 津波注意報、津波警報、大津波警報 | 「津波」「避難」+地名 |
| （将来）暴風・高潮・大雪・噴火 | 気象庁 | 各種注意報/警報/特別警報、噴火警報 | — |

### 4.2 選べるレベル（しきい値）

地点ごとに、災害種別ごとに「**タイムラインに表示する最低レベル**」と「**通知する最低レベル**」を選択できる。

| 種別 | 選択肢（しきい値） | デフォルト（表示 / 通知） |
| --- | --- | --- |
| 大雨・洪水・土砂災害 | 注意報以上 / 警報以上 / 特別警報のみ / OFF | 注意報以上 / 警報以上 |
| 地震 | 震度3以上 / 震度4以上 / 震度5弱以上 / 震度6弱以上 / OFF | 震度3以上 / 震度5弱以上 |
| 津波 | 津波注意報以上 / 津波警報以上 / 大津波警報のみ / OFF | 津波注意報以上 / 津波警報以上 |

- 内部では各情報を **共通の重要度（例: 1=情報, 2=注意報, 3=警報, 4=特別警報）** に正規化して保持し、しきい値判定を一本化する
- 津波は「海岸から一定距離内の地点」にのみ設定を表示する（内陸の地点では不要な選択肢を出さない）
- 気象庁の防災気象情報は**体系の見直し（レベル表記の導入など）が予定・実施されている**ため、名称は設定ファイル側で吸収し、内部の重要度で判定する設計にしておく（最新の体系は要確認）

### 4.3 設定イメージ

```
📍 自宅（半径3km）
  ┌──────────────┬────────────┬────────────┐
  │ 種別          │ 表示        │ 通知        │
  ├──────────────┼────────────┼────────────┤
  │ 大雨・洪水     │ 注意報以上  │ 警報以上    │
  │ 土砂災害       │ 警報以上    │ 警報以上    │
  │ 地震          │ 震度3以上   │ 震度5弱以上 │
  │ 津波          │ 注意報以上  │ 警報以上    │
  └──────────────┴────────────┴────────────┘
  ☑ 警報級以上のときだけ SNS の投稿も表示する
```

- 「警報級以上のときだけSNS投稿を表示」オプションで、平常時のノイズとSNS取得コストを抑える

## 5. 情報ソース方針（★コストの肝）

> X(Twitter) API は検索に有料プランが必要で、個人開発には高コスト。
> そのため **「公式情報を主軸、SNSは取得コストが低いものから段階的に」** を基本方針とする。

| 優先度 | ソース | コスト感 | 用途 | 備考 |
| --- | --- | --- | --- | --- |
| ◎ | 気象庁 防災情報XML / 気象庁JSON | 無料 | 警報・地震・雨の確定情報 | 利用規約に従いクレジット表示 |
| ◎ | P2P地震情報 API | 無料 | 地震速報 | レート制限に注意 |
| ○ | Threads API（キーワード検索） | 無料（要審査・制限あり） | 現場の声 | 権限・レート制限は要確認 |
| ○ | Bluesky（公開API / Firehose） | 無料 | 現場の声 | 日本語ユーザー増加中 |
| △ | 自治体の避難情報（RSS/オープンデータ） | 無料 | 避難指示・避難所開設 | 地域ごとに形式がバラバラ。将来対応 |
| × → 将来 | X API | 有料（高額） | 現場の声 | 法人プランの売上が立ってから検討 |

- **スクレイピングは行わない**（各SNSの規約違反リスクを避ける）
- SNS投稿は本文を丸ごと保存せず、**投稿ID・URL・要約メタ情報のみ保持し埋め込み表示**を基本とする（規約・プライバシー配慮）

## 6. 機能概要

### 6.1 共通機能

- 地点登録（住所入力 or 地図ピン、半径指定: 1km / 3km / 5km / 10km）
- 地点ごとのタイムライン（公式 / SNS をタブ or ラベルで区別）
- 地図表示（イベントをピン表示）
- 災害種別 × 警報レベルの選択（表示 / 通知を別々に設定。詳細は 4.2）
- 信頼度ラベル（公式 / 複数投稿で裏付けあり / 単独投稿）

### 6.2 toC 向け

- 無料プラン: 地点 2〜3件、Web閲覧のみ、通知はメール or Web Push
- 有料プラン（低価格）: 地点追加、LINE通知、過去履歴
- 家族共有（招待リンクで同じ地点を見られる）

### 6.3 toB 向け

- 組織・メンバー管理（管理者 / 閲覧者）
- 複数拠点の一括登録（CSVインポート）
- 拠点ダッシュボード（全拠点のステータス一覧: 平常 / 注意 / 警戒）
- 通知連携（Slack / Teams / メール）
- 拠点ごとのイベントログ出力（CSV）— BCP報告・振り返り用
- （将来）安否確認・社員への一斉連絡、API提供

### 6.4 toC / toB の違いまとめ

| 項目 | toC | toB |
| --- | --- | --- |
| 地点数 | 1〜10 | 10〜数百 |
| 主な画面 | タイムライン中心 | ダッシュボード（一覧・地図）中心 |
| 通知先 | メール / Web Push / LINE | Slack / Teams / メール |
| ユーザー | 個人＋家族 | 組織・ロール管理 |
| 課金 | フリーミアム（月数百円） | 拠点数ベースの月額 |
| 履歴 | 直近のみ | 長期保存・エクスポート |

## 7. 想定アーキテクチャ（低コスト前提）

```
[ユーザー]
    │
    ▼
CloudFront ── S3（Next.js 静的出力）
    │
    ▼
API Gateway (HTTP API)
    │
    ▼
Lambda (Go) ─── DynamoDB（地点 / イベント / ユーザー）
    ▲
    │
EventBridge Scheduler（数分おき）
    │
    ▼
Lambda (Go) 収集ワーカー
    ├─ 気象庁 / P2P地震情報
    ├─ Threads / Bluesky
    └─ 自治体RSS
          │
          ▼
     マッチング処理（地点×半径×種別）→ SNS/SES/Slack Webhook で通知
```

| レイヤ | 技術 | コスト方針 |
| --- | --- | --- |
| フロント | Next.js（App Router） | 可能な限り静的出力 + クライアントフェッチで S3/CloudFront に載せる。SSRが必要になったら Amplify Hosting / Lambda を検討 |
| バックエンド | Go（Lambda, `provided.al2023`） | 起動が速くLambdaと相性◎。常時起動サーバーは持たない |
| DB | DynamoDB（オンデマンド） | 低トラフィック時はほぼ無料枠内 |
| 地理検索 | Geohash をキーにした DynamoDB 設計 | RDS/PostGIS は固定費がかかるため初期は避ける |
| バッチ | EventBridge Scheduler + Lambda | 無料枠内で数分間隔の収集が可能 |
| 認証 | Cognito | 少人数なら無料枠内 |
| 通知 | SES / Web Push / Slack Webhook | 従量課金・低額 |
| 地図 | MapLibre GL + 無料タイル（国土地理院タイル等） | Google Maps の従量課金を避ける |
| IaC | Terraform（S3 backend + S3ネイティブロック） | 環境: dev / prod を別AWSアカウントに分離 |
| CI/CD | GitHub Actions（OIDCでAWS認証） | 詳細は [06](./06_deploy_flow.md) |

**月額目標: MVP段階で 約$15〜25/月**（セキュリティ対策込み。内訳は [05](./05_system_architecture.md) 7章）

> 詳細: 画面 [03](./03_screens.md) / データモデル [04](./04_data_model.md) / システム構成 [05](./05_system_architecture.md) / デプロイ [06](./06_deploy_flow.md) / セキュリティ [07](./07_security.md)

## 9. 非機能・留意事項

- **免責**: 本サービスは補助的な情報提供であり、避難判断は自治体・気象庁の公式情報に従う旨を明記
- **デマ対策**: SNS 投稿は「未確認」ラベルを基本とし、公式情報と明確に区別する
- **プライバシー**: 登録住所は暗号化保存、表示時は丸めた位置情報を使う。SNS投稿者の個人特定につながる加工はしない
- **規約順守**: 各API・データソースの利用規約、クレジット表記を守る
- **可用性**: 災害時はアクセスが集中するため、静的配信・キャッシュ中心で落ちにくい構成にする
