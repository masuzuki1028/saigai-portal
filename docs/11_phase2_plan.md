## 1. Phase 2 の目的

[01](./01_concept_overview.md) 1.4 のとおり、公式情報の通知だけなら無料の防災アプリで足りる。Phase 2 で**このサービスならではの価値**を作る。

1. **家族で同じ地点を見守れる**（家族共有・現地からの報告）
2. **公式発表より早い「現場の声」が、公式情報と区別されて並ぶ**（SNS の取り込み・信頼度ラベル）
3. **アプリを開かなくても気づける**（Web Push・時間帯指定通知）

あわせて、利用者を増やす前に必要な守り（WAF・パスキーなど。[07](./07_security.md) 7章）を入れる。

## 3. 進める順番（案）

外部の審査に時間がかかるものは**最初に申請だけ出し**、待つ間に外部に依存しない機能を作る。

| 段階 | 内容 | 理由 |
| --- | --- | --- |
| 2-0 準備 | Threads の審査の申請、Bluesky のアカウントとアプリパスワードの用意、SNS 検索の精度の PoC（01 10章の未決事項）、プライバシーポリシーの更新（SNS・Push・家族共有） | 審査は数週間かかることがある。PoC の結果で F5 の作り方が変わる |
| 2-1 | **F1 家族共有 → F2 報告**、あわせて **S1 WAF** | 外部の依存がなく、差別化の核。招待リンク・報告は外部から書き込める入口になるため、公開前に WAF を入れる |
| 2-2 | **F3 Web Push・F4 時間帯指定通知** | 通知の仕組み（matcher → notifier）の拡張。重複の排除（`SENT#`）をそのまま使える |
| 2-3 | **F5 SNS（Bluesky から）** | PoC の結果を見て作る。Threads は審査が通ってから足す |
| 2-4 | F6・F7・F8、S2〜S4 | 利用者が増える前に順次（S5 の DR は Phase 3 の前） |

## 4. 機能ごとの設計の要点

### 4.1 F1 家族共有

- データは 04 の `Organization(type=family)`・`Membership`・`Invite` をそのまま使う。地点の所有者は `OWNER#O#<orgId>`
- 招待リンクは推測できないトークン（128ビット以上）にし、DB にはハッシュだけを保存する（`INVITE#<tokenHash>`、TTL 付き）
- 認可は「家族のメンバーなら閲覧・報告できる」。個人の地点を家族の地点に移す操作を作るか（移すときの暗号化データの扱い）を決める
- 認可テスト: 家族でない利用者は、家族の地点・タイムライン・報告を読めない／書けない。招待トークンの使い回し・期限切れ
- 家族の誰に通知するか（全員か、通知をオンにした人だけか）

### 4.2 F2 現地からの報告

- TimelineItem の `kind=report`、`reliability=reported`。コメントは140字まで、ログに出さない（04 8章）
- 報告をきっかけにした通知はしない（04 5.4）。荒らし対策として、1人あたりの報告の回数に上限を付ける

### 4.3 F3 Web Push

- VAPID の鍵は SSM Parameter Store（SecureString）に置き、`notifier` だけが読める
- 購読（endpoint・鍵）は個人情報として扱い、アプリ層で暗号化して保存する。無効になった購読（410 Gone）は消す
- 送信先の URL は Push サービスのもの（`fcm.googleapis.com`、`web.push.apple.com` など）だけを許す（SSRF 対策。07 3.6）
- iPhone はホーム画面に追加したときだけ Push が届くため、Web App Manifest と、その案内の画面を用意する
- CSP に Service Worker を許可する（`worker-src 'self'`）

### 4.4 F5 SNS の取り込み

- 01 5章のとおり、本文は保存せず、URL・投稿時刻・推定位置・判定に使ったキーワードだけを残す（TTL 7日）。表示は埋め込み
- 取り込むのは「警報級が出ている地域」だけ（`snsOnlyWhenWarning`）。Threads は検索の回数に強い制限（7日で約500回という情報がある。要確認）があるため、地域と回数を絞る
- 位置の推定: 位置情報の付いた投稿は少ないため、本文の地名（市区町村名・駅名など）を辞書で照合する。辞書は国土数値情報などから作って同梱する
- 信頼度: 単独の投稿は `unverified`、近い場所・時間の複数の投稿は `corroborated`。SNS の投稿だけでは通知しない（01 6.1）
- Bluesky のアプリパスワードと Threads のトークンは SSM に置く。`ingest-sns` は DR では止めてよい（10 Tier 3）
